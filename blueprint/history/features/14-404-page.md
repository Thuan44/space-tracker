# Feature: 404 page

**From build-plan:** feature 14
**Build attempt:** 1
**Branch:** feature/404-page
**Status:** verified

## Goal

Any URL that doesn't match a real route (nonexistent path, mistyped ship/system
symbol used as a bare path, etc.) shows a "page not found" screen with a way
back to the app, instead of a blank router outlet or a confusing 404 from
nowhere.

## In scope

- A catch-all Vue Router route (`/:pathMatch(.*)*`) matching any URL not
  already claimed by an existing route.
- A static `NotFoundView` component: "page not found" message + a link back
  to `/`.
- No header/nav on this view, matching `/login`'s treatment in `App.vue`.
- Reachable with or without an agent token — a broken/unknown URL isn't an
  auth failure, so this route carries no `requireAuth`/`redirectIfAuthenticated`
  guard and behaves identically for logged-in and logged-out visitors.

## Out of scope

- The per-screen "error (retry)" states used by data-fetching views (Dashboard,
  Systems, Fleet, Market) - those cover failed API calls on a route that _does_
  exist, not an unmatched URL. Nothing about them changes here.
- Any change to existing routes' auth guards or ordering beyond appending the
  catch-all after them.

## Build steps

- [x] 1. Add the not-found view and wire it as the last route. - Create `src/features/not-found/views/NotFoundView.vue`: a centered
      message ("Page not found" or equivalent) and a `RouterLink` back to
      `/`, styled consistent with the existing surface/border/text tokens
      used elsewhere (e.g. `LoginView.vue`'s card treatment: `border-line`,
      `bg-surface-1`, `text-fg`/`text-muted`, `text-info` for the link). - In `src/router/index.ts`, import `NotFoundView` and append
      `{ path: '/:pathMatch(.*)*', name: 'not-found', component: NotFoundView }`
      as the last entry in `routes` (Vue Router matches in array order, so it
      must not precede any real route). No `beforeEnter` guard. - In `src/App.vue`, extend the existing header condition so it also hides
      on this route: `v-if="route.name !== 'login' && route.name !== 'not-found'"`. - Done when: running the dev server and navigating to an unmatched path
      (e.g. `/nonexistent`) renders `NotFoundView` with no header/nav and a
      working link back to `/`; all existing routes still resolve normally;
      `npm run type-check` and `npm run build` both pass.

## Testing

No test runner scope applies here: per the Testing standard's scope rule, this

## Notes for the AI

- Route matching order matters: Vue Router resolves top-to-bottom, so the
  catch-all must be the last entry or it will swallow every other route.
- Mirror `/login`'s existing pattern for "no header" (`App.vue`'s `v-if` on
  `AppHeader`) rather than introducing a second mechanism (e.g. a route meta
  field) for the same concern.
- Keep the view static: no query, no loading/error branches - there is nothing
  to fetch.
